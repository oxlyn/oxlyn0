# Oxlyn 项目整体评审报告

**评审日期：** 2026-09-12
**评审范围：** 全仓库（源码 / 文档 / 构建产物 / 部署链路 / 脚本）
**HEAD：** `eb832f8`（main），工作区干净

---

## 总体结论

工程质量**明显高于**同类"AI 生成 demo 改造"项目：TypeScript 严格通过、零 `console.*`、零 `TODO/FIXME`、零 `any`、零 `@ts-ignore`、零 `dangerouslySetInnerHTML`，系统层（窗口管理、拖拽 rAF 节流、iframe keep-alive）设计得相当克制且注释到位。

问题不在代码质量，而在**三个系统性缺口**：

1. **部署链路断了** —— 线上站点停留在 6 天前（10 个 commit 未上线）。
2. **文档与代码已经脱节** —— 两份主文档给出的操作指引会把人引向错误结果，其中一条还会**覆盖用户的手工修改**。
3. **产品层面缺两件事** —— 移动端完全不可用；Trash 是个永远空的死胡同。

以下按严重程度分级。

### P0-2　全屏 Launchpad 是不可达的死代码，且存在两份实现

**现象：** `app/src/system/components/Launchpad.tsx` 永远不会渲染。

**证据：**
- `App.tsx:32` 定义 `const [launchpad, setLaunchpad] = useState(false)`。
- 全仓库只有 `setLaunchpad(false)`（`App.tsx:51`、`App.tsx:83`），**没有任何一处 `setLaunchpad(true)`**。
- 因此 `App.tsx:83` 的 `{!focusId && launchpad && <Launchpad/>}` 恒为 false。
- 同时 `app/src/apps/launchpad/app.tsx` 是**另一份**完全不同的 Launchpad 实现（按分类分组的窗口版），由 Dock 的 "Apps" 图标打开。

**影响：** 两套并行实现，一份是死的；快捷键（`Cmd+K` / `Ctrl+Space`）只唤出 Spotlight，没有通往全屏 Launchpad 的路径。macOS 原生的 `F4` / 五指挥入 体验缺失。

**修复：** 二选一 —— 要么删掉 `system/components/Launchpad.tsx`，要么给 Dock 的 Apps 图标接上全屏版并删除窗口版。

### P0-4　Trash 是死胡同：有入口，无出口

**现象：** Dock 上有垃圾桶图标，点开是 Finder 的 `trash` 文件夹 —— 但**没有任何办法把文件放进去**。

**证据：** `fs` store 提供了完整的文件操作 API，但从未被 UI 调用：

| API | 定义位置 | 调用方 |
|---|---|---|
| `trash()` | `stores/fs.ts:64` | **无** |
| `emptyTrash()` | `stores/fs.ts:70` | **无** |
| `rename()` | `stores/fs.ts:55` | **无** |
| `move()` | `stores/fs.ts:58` | **无**（仅被 `trash()` 内部调用，而 `trash()` 本身没被调用） |

**影响：** Finder 里既不能删除、也不能重命名、也不能拖拽移动文件。垃圾桶永远空，且没有"清空"操作。整个虚拟文件系统是只读的（除了 TextEdit 的 `setContent`）。

**附带：** `windows.ts:40` 的 `setPayload()` 同样从未被调用。

### P0-5　`minimize()` 会把焦点交给隐藏的休眠窗口

**证据：** 对比两处逻辑：

- `windows.ts:148`（`close`）—— 正确地排除了 dormant：`rest.filter((w) => !w.dormant && !w.minimized)`
- `windows.ts:164`（`minimize`）—— **没有排除 dormant**：`s.wins.filter((w) => w.id !== id && !w.minimized)`

**影响：** 关闭一个 keep-alive 窗口（study / wakfu / devkit）使其进入休眠后，再最小化另一个窗口，`focusedId` 可能落到这个**不可见的**休眠窗口上。此时：

- `MenuBar.tsx:74` 的 `wins.find((w) => w.id === focusedId && !w.minimized)` 会把它当成前台应用，菜单栏显示出错误的 App 名；
- 用户看到菜单栏亮着一个"没有窗口"的应用。

**修复：** `minimize` 里的过滤条件加上 `!w.dormant`，与 `close` 保持一致。

## P1 — 文档与流程（会误导操作，且有一条会丢数据）

### P1-1　文档说"37 个应用"，实际 34 个

- `README.md:95`："all **37** apps as self-registering modules"
- `CUSTOMIZE.md:101`："**37** apps in `src/apps`"
- 实际：`app/src/apps/` 下 34 个应用目录（外加一个 `README.md`）

### P1-2　`CUSTOMIZE.md` 第 1 节（换媒体）已经完全失效

文档让人"用同名文件替换"，但**扩展名和文件名都对不上**：

| CUSTOMIZE.md 写的 | 代码里实际引用的 |
|---|---|
| `wallpaper-tahoe-day.jpg`（默认） | `wallpaper-graphite.svg`（默认，`stores/system.ts:37`） |
| `wallpaper-bigsur.jpg` | 不存在 |
| `photo-1.jpg` … `photo-8.jpg` | `/macos27/photo-1.svg`（`apps/photos/data.ts:11`） |
| `cover-1.jpg` … `cover-4.jpg` | `/macos27/cover-1.svg`（`apps/music/data.ts:14`） |
| `import.jpg` | 不存在 |

**影响：** 照做的人放进 `.jpg` 后**什么都不会变**，而且不会报错 —— 最难排查的那类问题。

**补充：** README 说 "Photos — Skylar 🐾"，但所有媒体都是 `scripts/gen-media.mjs` 生成的渐变 SVG 占位图（每张约 545 B），不是照片。这个取舍本身是合理的（1 KB vs 2.7 MB），但文档读起来像真的发了照片。

### P1-3　⚠️ 关于生成文件的指引自相矛盾，且会覆盖手工修改

**同一批文件，两份文档给出相反指令：**

- 每个 `data.ts` 文件头（如 `apps/photos/data.ts:1-4`）：
  > GENERATED by scripts/sync-extracted.mjs … **Edit /tmp/extracted/*.json + re-run the script instead of editing.**
- `CUSTOMIZE.md:33-35`：
  > They're plain source files now — **edit them directly**.

**而 `scripts/sync-extracted.mjs` 的行为是危险的：** 它整体覆写 14 个 `data.ts`（`:103`）+ `fs-seed.ts`（`:49`）+ `notes-seed.ts`（`:78`），没有任何合并或确认。

**后果：** 任何人按 CUSTOMIZE 的建议直接编辑 `data.ts`，之后再跑一次 sync，**所有手工内容被静默清空**。

**修复：** 明确单一事实来源 —— 要么承认这些是普通源文件、删除 sync 脚本与文件头警告，要么保留生成流程并移除 CUSTOMIZE 里的"直接编辑"建议。

### P1-4　文档给出的"重新生成"路径已经走不通

- `sync-extracted.mjs:7` 读取 `/tmp/extracted/*.json` —— **临时目录，早已不存在**；仓库里的 `extracted/` 是空目录，也没有任何提取 JSON 被提交。
- `CUSTOMIZE.md:34-35` 说要"对 `assets/index-Bfk0NWYJ.js`（保留在 git 历史中）重新提取" —— 但 `assets/` 里实际是 **`index-CYPqmNtY.js`**，文件名对不上。
- 提取脚本本身（"one-off bundle-extraction scripts"）不在仓库里。

**结论：** 从零重建 seed 数据的流程**事实上不可复现**。当前只能靠 git 历史里的生成结果。

### P1-5　`deploy-root.sh` 会删掉文档让你保留的文件

`scripts/deploy-root.sh:12`：

```bash
rm -rf assets
```

每次部署都会删除 `assets/`（含 `index-CYPqmNtY.js`）。而 `CUSTOMIZE.md:34` 明确说这个文件"保留在 git 历史中"供日后重新提取使用 —— 脚本却把它从工作区抹掉。只能靠 git 恢复。

## P2 — 产品与体验

### P2-1　移动端完全不可用（最大的产品缺口）

- `app/src/index.css` 全文**没有任何 `@media` 查询**。
- Dock（`Dock.tsx:33-34`）是 `flex justify-center`，**没有 max-width、没有 overflow 处理**；当前约 15 个图标 × ~52px ≈ 830px，在手机上会被裁掉两端。
- 窗口 `minSize` 下限是 420–640px 宽（如 `finder` 560、`settings` 620、`launchpad` 640），**超过手机视口宽度**。
- 桌面图标固定 `w-24`（`Desktop.tsx:42`）。

**为什么重要：** 这是一份简历。简历链接的打开场景大概率是手机。`vite.config.ts:70` 还设了 `server.host: true`（局域网可访问），但真机上体验是坏的。

### P2-2　"Oxlyn" 品牌改造没有完成

"macOS 27" 仍散落在多个面向用户的表面：

| 位置 | 内容 |
|---|---|
| `apps/settings/app.tsx:137` | `macOS 27 — Golden Gate` |
| `App.tsx:23` | `document.title = \`${name} — macOS 27\`` |
| `stores/system.ts:47` | localStorage key `macos27.system` |
| `vite.config.ts:16` | base path `/macos27/` |
| `apps/settings/app.tsx:145` | `Apps: self-registering — see src/apps/`（面向访客暴露源码路径） |

而 `<title>` 已是 `Oxlyn — Interactive Resume`。需要决定 "macOS 27" 是**刻意的致敬**还是**遗留** —— 目前两种信号同时存在。

### P2-3　界面语言中英混排

`apps/settings/app.tsx` 的 Appearance 面板：面板标题是英文（Appearance / Wallpaper / About / Light / Dark），但标题栏透明度控件整段是中文：

- `:80` `窗口标题栏透明度`
- `:92-93` `0% 不透明（默认）→ 100% 全透明，只保留红黄绿按钮。对所有应用窗口即时生效。`

另外 `apps/notes/app.tsx:51` 把侧边栏分组写死为 "iCloud"，但 `travel` 文件夹的 account 是 `On My Mac`（`stores/notes.ts:9`）—— 分组标签与实际归属不符。

### P2-4　深色主题首屏闪烁（FOUC）

`app/index.html:2` 把 `class="dark"` 和 `data-theme="dark"` **硬编码**在 `<html>` 上；`App.tsx:41-44` 才在 `useEffect` 里应用持久化的主题 —— 也就是**首帧之后**。

**后果：** 任何把主题设为 light 的用户，每次加载都会先闪一下深色。zustand 的 `persist` 在 store 创建时同步读到 localStorage，但 React 渲染在其后，所以窗口期真实存在。

**修复：** 在 `<head>` 里加一段内联脚本，绘制前读 localStorage 并设置 class。

### P2-5　缺少分享用的元数据

`app/index.html` 只有 `description`，没有 `og:title` / `og:image` / `og:url` / `twitter:card` / `theme-color`。

**后果：** 简历链接发到微信 / Slack / X 时，预览卡片是空白或纯文本 —— 而这份东西的全部意义就是被分享。

### P2-6　第三方运行时依赖违背了项目自己的既定原则

项目**特意移除了 Google Fonts**，理由是"在 Google 不可达的网络上实测阻塞首屏数秒"（`index.css:71-73`、`README.md:95`）。但同类依赖仍然存在：

| 依赖 | 位置 | 备注 |
|---|---|---|
| `commondatastorage.googleapis.com` | `apps/tv/data.ts:9` | **同样是 Google 域名** |
| `interactive-examples.mdn.mozilla.net` | `apps/tv/data.ts:14,19` | |
| `api.dictionaryapi.dev` | `apps/dictionary/app.tsx:27` | |
| `api.open-meteo.com` | `apps/weather/app.tsx:38` | |
| `duckduckgo.com` | `apps/safari/app.tsx:31` | |

这些在当初促使他们删字体的**同一类网络环境**下同样不可达。另外还有隐私面：访客 IP 会暴露给这些第三方。

**建议：** 至少让 TV / Dictionary / Weather 在请求失败时优雅降级，而不是空面板。

### P2-7　笔记与文件系统不持久化，与系统设置不一致

- `stores/system.ts:46` 用了 zustand `persist` —— 主题、壁纸、标题栏透明度能存活刷新。
- `stores/notes.ts:47` 和 `stores/fs.ts:45` **没有** persist。

**后果：** 访客写的笔记、置顶、打的标签、新建的文件夹，**刷新即全部丢失**。与 "Log in and explore" 的定位相冲突。

### P2-8　无障碍（a11y）缺口

- **键盘不可达：** 桌面图标（`Desktop.tsx:45`）和 Finder 行（`apps/finder/app.tsx:112,138`）只在 `onDoubleClick` 上触发打开，元素本身不可聚焦，键盘用户无法打开任何文件。
- **无可见焦点：** 全仓库没有任何 `:focus-visible` 样式；大量自定义按钮在键盘导航时看不到焦点位置。
- **图标按钮无名称：** Finder 的 后退 / 前进 / 图标视图 / 列表视图 四个按钮（`apps/finder/app.tsx:72-101`）没有 `title` 也没有 `aria-label`，读屏器只能读出"按钮"。
- **菜单栏无键盘导航：** `MenuBar.tsx` 的 `Menu` 组件不支持方向键 / Escape 遍历，`mousedown` 之外无交互。
- **动画无降级：** `index.css:60-72` 的 `win-in` / `focus-in` / `fade-in` 始终执行，没有 `@media (prefers-reduced-motion: reduce)`。
